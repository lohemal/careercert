# 방과후 강사 경력관리 및 경력증명서 발급 시스템 — 설계안

- 작성일: 2026-10-01
- 상태: **승인됨 (2026-10-01)** — 결정 D1~D13 과 추가 조건은 §15 에 확정. 본문과 §15 가 다르면 §15 가 우선한다.
- 분석 대상: `방과후 강사 경력증명서 샘플.xlsm` (시트 2개, VBA 모듈 1개 + 시트 이벤트 1개)

## 1. 기존 Excel/VBA 분석

### 1.1 파일 구성

| 구성 | 내용 |
|---|---|
| 시트 `경력증명서` | 인쇄 양식. 인쇄 영역 `A1:G26`, A4 세로, 배율 86% |
| 시트 `강사명단` | 경력 목록. 한 줄 = 경력 1건. 열: `성명 · 프로그램명 · 직위 · 시작날짜 · 마감날짜 · 지도사항` |
| `Sheet1.Worksheet_Change` | `D6`(성명)이 바뀌면 실행. 비우면 `B10:F14, G6, D7, B2` 를 지우고, 값이 있으면 `FillCareerCertificate` 호출 |
| `Module1.FillCareerCertificate` | `강사명단` 2행부터 끝까지 돌며 A열 == D6 인 줄을 찾아 10행부터 한 줄씩 적는다 |

### 1.2 양식의 셀 배치 (실제 출력으로 확인)

| 위치 | 내용 | 채우는 방법 |
|---|---|---|
| A2 / B2 | `발급번호:` / 번호 | 직접 입력 |
| A4 | **`방과후학교 개인위탁 외부강사 활동 확인서`** (18pt 굵게) | 고정 |
| B6~D6 | `성 명` · `한 글` · 성명 | **D6 입력 → 매크로 발동** |
| F6 / G6 | `주민번호` / 번호 | 직접 입력 |
| B7 / D7 | `주 소` / 주소 | 직접 입력 |
| A8:A14 | `경력사항` (세로 글자) | 고정 |
| B8~F9 | 머리글 `기간(부터·까지) · 프로그램명 · 직위 · 지도사항` | 고정 |
| B10:F14 | **경력 5줄 고정** | 매크로 |
| A15 / B15:G15 | `용도` / `기관제출` | 기본값, 직접 수정 |
| C17 | `위와 같이 증명합니다.` | 고정 |
| C19 | `=TODAY()` (표시 형식 `mm-dd-yy`, 이 PC 에선 `2026-10-01`) | 수식 |
| C21 | `○○초등학교장 (직인)` | **하드코딩** |
| A23~B25 | `담당부서 · 담당자 · 전학번호` / `○○초등학교 · 홍길동 (인) · 000-000-0000` | **하드코딩** |

매크로의 열 대응: 명단 D(시작)→B, E(마감)→C, B(프로그램)→D, C(직위)→E, F(지도사항)→F.

### 1.3 실제로 돌려서 확인한 문제 (샘플 사본에서 시험)

| # | 문제 | 확인 방법 · 결과 | 앱에서의 대응 |
|---|---|---|---|
| E1 | **다른 강사로 바꾸면 앞 사람의 주민번호·주소·발급번호가 남는다** | 김으뜸에 주민번호·주소·발급번호를 넣고 성명만 박으뜸으로 바꿈 → 세 칸이 그대로 남음. 성명을 **비울 때만** 지운다 | 강사를 바꾸면 발급 입력값 전체를 새로 시작. 개인정보가 다른 사람 증명서로 새는 길을 구조적으로 막는다 |
| E2 | **경력이 5건을 넘으면 양식을 덮어쓴다** | 이으뜸 경력을 7건으로 늘림 → 6번째가 15행(`용도` 병합 칸)을 덮고, 7번째는 표 밖 16행에 찍힘. 경고 없음 | 줄 수 제한 없음. 넘치면 다음 쪽으로 표를 이어 쓴다(§7.4) |
| E3 | 강사를 바꿔도 **앞 사람의 경력 줄이 남을 수 있다** | 매크로가 B10:F14 를 지우지 않고 덮어쓰기만 함 → 새 강사의 경력이 더 적으면 남는 줄이 그대로 인쇄됨 | 증명서 내용은 매번 선택한 경력에서 새로 만든다 |
| E4 | 발급일이 `=TODAY()` | 파일을 열 때마다 날짜가 바뀜. 지난 증명서를 다시 뽑으면 날짜가 달라짐 | 발급일은 입력값(기본 오늘)이고 발급 확정 때 고정 저장 |
| E5 | 발급 기록이 없다 | 인쇄하고 나면 무엇을 누구에게 발급했는지 남지 않음 | 발급 스냅샷(§4.4) |
| E6 | 날짜가 **글자**다 | `2022.3.4.` · `2023.2.10.` — 0 채움 없음, 끝 마침표, 글꼴도 줄마다 다름(Arial/맑은 고딕/굴림) | 날짜 형식으로 저장, 출력은 `2022.03.04` 로 통일 |
| E7 | 성명 **완전 일치**로만 찾는다 | 뒤 공백 하나로 못 찾음. **동명이인은 한 사람으로 합쳐짐** | 강사를 번호로 식별. 이름은 검색 수단일 뿐 |
| E8 | 학교 정보 하드코딩 | 학교장 표기·담당자가 셀에 박혀 있음. `담당부서` 칸에 학교명이 들어가 있고 `전학번호` 는 `전화번호` 오타로 보임 | 설정 화면 값으로 채움 |
| E9 | 출력이 PC·프린터에 따라 달라진다 | 이 PC 의 Excel 로 PDF 를 떠 보니 **G열이 2쪽으로 잘려 나감**(배율 86% 고정, 쪽 맞춤 없음) | 한 가지 렌더링 엔진으로 미리보기·인쇄·PDF(§7) |
| E10 | 지도사항 칸이 F열 하나 | 머리글은 F:G 병합인데 10~14행은 병합 안 됨 → 긴 글은 옆 칸으로 넘치거나 잘림 | 칸 안에서 줄바꿈 |
| E11 | 순서 | 명단 시트에 적힌 차례 그대로 | 시작일 오름차순 기본, 사용자가 고른 것만 |

샘플 명단에는 `현재` 가 없지만 요구사항대로 실제 자료에는 있다고 보고 가져오기에서 처리한다(§9).

### 1.4 현재 업무 흐름

```
강사명단 시트에 경력 누적(학년도마다 한 줄씩 손으로 추가)
  → 경력증명서 시트 D6 에 성명 입력 → 매크로가 경력 5줄 채움
  → NEIS 민원 등록 → 발급번호 받아 B2 에 입력
  → 주민번호(G6)·주소(D7) 입력, 용도 확인
  → 인쇄(발급일은 오늘 날짜 자동) → 직인
  → 파일 저장하지 않거나 덮어씀 → 기록 없음
```

### 1.5 요구사항과 기존 파일의 차이

| 항목 | 기존 파일 | 요구사항 | 비고 |
|---|---|---|---|
| **문서 제목** | `방과후학교 개인위탁 외부강사 활동 확인서` | "경력증명서" | **결정 필요 D1** |
| 성명 옆 `한 글` 칸 | 있음(한자 칸 흔적) | 언급 없음 | 양식 유지 여부 D1 에 포함 |
| 경력 줄 수 | 5줄 고정 | 제한 없음, 쪽 넘김 고려 | |
| 종료일 `현재` | 글자 | NULL + 상태 | |
| 발급일 | TODAY() | 기본 오늘, 수정 가능, 고정 저장 | |
| 발급 기록 | 없음 | 스냅샷 + 이력 + 재출력 | |
| 직인 | `(직인)` 글자 | 언급 없음 | 직인 이미지는 넣지 않는 것을 기본으로 제안(D8) |

## 2. 기술 구성

**요청하신 구성 그대로 간다: Tauri 2 + React + TypeScript + Rust + SQLite(rusqlite bundled).**
보결·학생명단·출석부 등 이미 같은 구성으로 배포·자동 업데이트까지 검증한 틀이 있어 다른 구성을 고를 이유가 없다.
그 저장소들에서 검증된 것(마이그레이션 러너, SQLite 백업 API, 복원 대기 파일 방식, 태그 하나로 릴리스, 업데이터 서명)을 그대로 옮긴다.

| 항목 | 값 |
|---|---|
| 폴더 | `%USERPROFILE%\Documents\방과후경력증명서 발급 시스템` |
| identifier | `kr.school.careercert` (자료: `%APPDATA%\kr.school.careercert\`) |
| 실행 파일 | `career-cert` (ASCII — 한글 앱 이름으로 릴리스가 깨졌던 전례) |
| Vite 포트 | **1450** (1420·1421·1430·1440 은 다른 앱이 사용 중 — Phase 0 에서 확인) |
| 연습용 자료 | `kr.school.careercert.sandbox` 로 분리 (`npm run app:sandbox`) |

## 3. 아키텍처

```
┌──────────────── React + TS (화면만) ────────────────┐
│ pages/  대시보드 · 강사 · 발급 · 이력 · 설정          │
│ api/    invoke 래퍼(타입 정의는 Rust 와 1:1)          │
└──────────────┬───────────────────────────────────────┘
               │ Tauri command (얇게: 입력 받기 → service 호출 → 결과)
┌──────────────▼──────────── Rust ─────────────────────┐
│ commands/  Tauri 에만 묶인 층                          │
│ service/   업무 절차: 발급 확정, 가져오기, 백업·복원    │  ← 서버가 생기면 여기를 그대로 옮긴다
│ domain/    순수 규칙: 기간 표시, 발급번호 검사, 주민번호 형식, │
│            증명서 문서 모델(CertificateDoc), 날짜 파싱  │  ← DB·Tauri 모름, 단위 시험 대상
│ render/    CertificateDoc → HTML (양식 버전별)         │
│ print/     WebView2 로 PDF 만들기 · 인쇄 (Windows 전용) │
│ repo/      SQL (표마다 한 파일)                         │
│ crypto/    민감정보 암호화(DPAPI + AES-GCM)             │
│ db/        연결, 마이그레이션, 백업 API                  │
└───────────────────────────────────────────────────────┘
```

원칙:
- **화면은 규칙을 모른다.** "현재" 표시, 발급 가능 여부, 날짜 해석은 모두 `domain` 에 있고 화면은 결과만 보인다.
- **증명서 내용을 만드는 곳은 `domain::certificate::build` 하나.** 미리보기·발급·재출력·새 증명서 복사가 모두 이 함수를 지난다.
- **출력은 `render` 하나.** 미리보기·인쇄·PDF 가 같은 HTML 을 같은 엔진(WebView2)으로 그린다.

## 4. 데이터 모델

### 4.1 큰 그림 — 두 세계를 나눈다

```
[현재 자료 — 고칠 수 있다]                  [발급 기록 — 고칠 수 없다]
 school_settings (1행)                      certificates ──< certificate_items
 instructors ──< careers                        │
        ▲             ▲                         │ (참고용 번호만, 없어도 됨)
        └─────────────┴─────────── source_* ────┘
                                            certificate_outputs (인쇄·PDF 기록)
 imports (가져오기 작업)   audit_log (누가 무엇을)
```

발급 기록은 현재 자료를 **참조하지 않고 복사한다.** `source_instructor_id`, `source_career_id` 는 "어디서 왔는지" 추적용일 뿐, 출력에는 절대 쓰지 않는다. 강사를 지워도(`ON DELETE SET NULL`) 증명서는 그대로 열린다.

### 4.2 현재 자료

**school_settings** (행 1개, `id = 1` 고정)

| 필드 | 형식 | 설명 |
|---|---|---|
| school_name | TEXT NOT NULL | 예: `○○초등학교` |
| certificate_title | TEXT NOT NULL | 문서 제목. 기본 `방과후학교 개인위탁 외부강사 활동 확인서` (D1) |
| issuer_title | TEXT NOT NULL | 발급자 표기. 기본은 `{school_name}장` 으로 채워 주되 따로 고칠 수 있게 (예: `○○초등학교장`) |
| department | TEXT | 담당부서 |
| manager_name | TEXT | 담당자 |
| phone | TEXT | 전화번호 |
| default_purpose | TEXT NOT NULL DEFAULT '기관제출' | |
| updated_at | TEXT | |

**instructors**

| 필드 | 형식 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| uuid | TEXT UNIQUE NOT NULL | 서버 확장 대비 전역 식별자 |
| name | TEXT NOT NULL | 공백 정리 후 저장 |
| distinguisher | TEXT | 동명이인 구분 메모(예: 생년 `1985`, `마술`) — 선택 |
| phone | TEXT | 선택 (지금 업무에 필요 없으면 빼도 됨) |
| memo | TEXT | |
| archived_at | TEXT | 보관 처리(목록에서 숨김). **삭제 대신 보관이 기본** |
| created_at / updated_at | TEXT | |

주민번호·주소는 **강사 원장에 두지 않는다**(§8, 결정 D3).

**careers**

| 필드 | 형식 | 설명 |
|---|---|---|
| id, uuid | | |
| instructor_id | INTEGER NOT NULL FK | |
| program_name | TEXT NOT NULL | 프로그램명 |
| position | TEXT NOT NULL DEFAULT '강사' | 직위 |
| duty | TEXT NOT NULL | 지도사항 (가져오기·입력 시 기본 `방과후학교 {프로그램명}` 제안) |
| start_date | TEXT NOT NULL | `YYYY-MM-DD` |
| end_date | TEXT NULL | **재직중이면 NULL.** `"현재"` 같은 글자는 저장하지 않는다 |
| status | TEXT NOT NULL | `ACTIVE`(재직중) · `ENDED`(종료) |
| end_reason | TEXT | `CONTRACT_END`(계약만료) · `TERMINATED`(중도해지) · NULL |
| import_id | INTEGER FK NULL | 어느 가져오기에서 왔는지 |
| memo, created_at, updated_at, archived_at | | |

제약:
```sql
CHECK ( (status = 'ACTIVE' AND end_date IS NULL)
     OR (status = 'ENDED'  AND end_date IS NOT NULL AND end_date >= start_date) )
```
상태와 종료일이 어긋나는 행은 DB 가 받지 않는다. "종료일은 지났는데 재직중" 같은 경우(학년도가 끝났는데 종료 처리를 안 함)는 막지 않고 **대시보드에 "종료 처리 확인" 으로 알린다.**

### 4.3 증명서 문서 모델 (코드 안의 구조, DB 표 아님)

```rust
struct CertificateDoc {
    template_version: u32,          // 어떤 양식으로 그렸는지
    title: String,                  // 문서 제목
    issue_no: String,
    issued_on: Date,
    purpose: String,
    holder: Holder { name, rrn, address },
    items: Vec<Item { start_date, end_date: Option<Date>, program_name, position, duty }>,
    school: SchoolBlock { issuer_title, department, manager_name, phone },
}
```
기간 표시(`2026.03.04 ~ 현재`)는 `end_date == None` 일 때 **그리는 순간에만** 만든다. 저장되는 것은 언제나 날짜 또는 NULL.

### 4.4 발급 기록 (불변)

**certificates**

| 필드 | 설명 |
|---|---|
| id, uuid | |
| issue_no | 발급번호(입력 그대로) |
| issue_no_key | 중복 비교용. **앞뒤 공백만 뺀 값 그대로**(D9 — 앱이 형식을 바꾸지 않는다) |
| issued_on | 발급일 |
| purpose | 용도 |
| holder_name | 성명 (검색용 평문) |
| sensitive_blob | **암호화된** `{rrn, address}` (§8) |
| rrn_masked | 목록 표시용 `850315-1******` |
| title, issuer_title, department, manager_name, phone | 발급 당시 학교 정보 **복사본** |
| template_version | 발급 당시 양식 버전 |
| doc_hash | 문서 내용(정규화 JSON)의 SHA-256 — 나중에 내용이 바뀌지 않았는지 확인 |
| status | `ISSUED` · `VOIDED` |
| void_reason, voided_at | 발급 취소(무효) 시에만 |
| source_instructor_id | 참고용, `ON DELETE SET NULL` |
| copied_from_id | "이 내용으로 새 증명서 작성" 의 원본 |
| created_at, created_by | `created_by` 는 지금은 `local` — 서버에서 사용자 번호가 들어갈 자리 |

**certificate_items**: `certificate_id, seq, start_date, end_date(NULL=당시 재직중), program_name, position, duty, source_career_id(참고용)`

불변 보장 — 코드 규칙이 아니라 **DB 트리거**로 건다:
```sql
-- certificate_items 는 UPDATE/DELETE 전면 금지
-- certificates 는 status·void_reason·voided_at 을 ISSUED→VOIDED 로 바꾸는 것만 허용
```
발급번호 중복: `UNIQUE(issue_no_key) WHERE status = 'ISSUED'` (취소된 것과는 겹쳐도 됨).

**예시로 확인하는 요구사항 §8**
2026-09-30 발급 → items 에 `start 2026-03-04, end NULL` 저장.
10-31 에 경력을 `ENDED, 2026-10-31` 로 고쳐도 careers 만 바뀐다. 9-30 증명서를 열면 items 의 NULL 을 그려 `2026.03.04 ~ 현재`. (Phase 6 자동 시험으로 고정한다.)

**certificate_outputs**: `certificate_id, kind(PREVIEW/PRINT/PDF), at, note` — 재출력 이력. 파일 경로는 저장하지 않는다(개인정보가 든 파일 위치를 남기지 않기 위해; 필요하면 D9).

### 4.5 기타

- **imports**: `id, file_name, file_hash, sheet, mapping_json, rows_total, added, skipped, created_at`
- **audit_log**: `at, action, target_type, target_id, summary` — 주민번호·주소는 절대 적지 않는다.
- 스키마 버전: `PRAGMA user_version` + `migrations/001_init.sql` (배포 후 001 동결, 이후 002…).

- 발급번호가 비어 있으면 [발급 확정] 이 눌리지 않고 이유를 버튼 옆에 적는다.

## 6. 발급 절차 (상태)

```
[작성 중] --발급번호 입력·검증 통과--> [확정 가능] --확정--> ISSUED --취소(사유)--> VOIDED
   (메모리에만, DB 저장 안 함)                           │
                                                       └─ 인쇄/PDF (횟수 제한 없음, 기록만)
```
- 작성 중 내용(주민번호 포함)은 DB 에 저장하지 않는다(D6).
- 확정은 한 트랜잭션: 입력 재검증 → 발급번호 중복 확인 → 학교 정보·경력을 **그 순간 값으로** 복사 → 트리거가 잠금.
- 고칠 일이 생기면: 기존 건 **발급 취소(사유 기록)** → "이 내용으로 새 증명서 작성" → 새 번호로 발급. 지우는 버튼은 없다.
- 서버 확장 시 `REQUESTED → APPROVED` 가 `ISSUED` 앞에 붙는 구조라 지금 모델을 바꾸지 않아도 된다.

## 7. 출력(미리보기·인쇄·PDF)

### 7.1 선택: HTML 양식 한 벌 + WebView2 한 엔진

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. HTML/CSS 양식 → WebView2 `PrintToPdf` · `Print`** (제안) | 미리보기·PDF·인쇄가 같은 Chromium 엔진. 표 쪽 넘김·머리글 반복을 CSS 로. 한글 글꼴 자동 포함. 서버에선 headless Chromium 으로 같은 HTML 사용 가능 | WebView2 COM 을 Rust 에서 직접 부르는 부분을 초기에 검증해야 함 |
| B. Rust 로 PDF 직접 그리기(lopdf 등) | 결과 완전 고정 | 표 배치·줄바꿈·쪽 넘김을 손으로 계산. 미리보기에 PDF 렌더러 필요 |
| C. Excel 양식에 값 채워 COM 출력 | 기존 양식 그대로 | Excel 설치 필요, 느림, PC 마다 결과 다름(E9 그대로) |

### 7.2 흐름

```
CertificateDoc ──render(template_version)──> HTML(@page A4, 글꼴 내장)
   ├─ 화면 미리보기: 같은 HTML 을 iframe 에 (입력하는 동안 즉시 갱신)
   ├─ [PDF 미리보기]/[PDF 저장]: 숨은 WebView2 창에 HTML 을 올리고 PrintToPdf → PDF 바이트
   │                            미리보기는 이 PDF 를 WebView2 내장 PDF 뷰어로 보여 준다(쪽 나뉨까지 실제와 같음)
   └─ [인쇄]: 같은 숨은 창에서 Windows 인쇄 대화상자(프린터 선택) — 여백·배율·머리글/바닥글은 앱이 고정
```

### 7.3 재현성

- 양식 HTML/CSS 는 **버전을 매겨 코드에 영구 보관**한다(`render/v1.rs`, `v2.rs` …). 양식을 고쳐도 옛 증명서는 옛 버전으로 그린다.
- 글꼴: 시스템 글꼴 대신 **앱에 글꼴 파일을 넣어** PC·서버와 상관없이 같은 모양(D7).
- 발급 확정 시 PDF 파일 자체를 저장할지는 D5 에서 결정(암호화 필요).

### 7.4 쪽 넘김

- 기본 5줄 칸을 유지(빈 줄로 채워 기존 양식과 같은 모양). 경력이 더 많으면 표가 늘어나고, 한 쪽에 들어갈 줄 수를 넘으면 다음 쪽으로 **머리글(기간·프로그램명…)을 반복하며** 이어진다.
- `위와 같이 증명합니다 · 발급일 · 학교장 · 담당자` 블록은 쪼개지지 않게(`break-inside: avoid`) 마지막 쪽에.
- 2쪽 이상이면 쪽마다 `발급번호 · 성명 · n/전체` 바닥글 — 한 장이 빠지거나 섞이는 것을 막는다.
- 시험: 경력 1·5·6·15·40건으로 PDF 를 만들어 쪽 수와 잘림 없음을 자동 확인.

### 7.5 위험 요소와 검증 순서

WebView2 의 `PrintToPdf`/인쇄 API 는 Tauri 가 직접 감싸 주지 않아 `webview2-com` 으로 부른다. **Phase 5 첫 작업을 이 검증(스파이크)으로 한다.** 막히면 대안: PDF 만 A 방식으로 만들고 인쇄는 그 PDF 를 WebView2 PDF 뷰어의 인쇄로 보낸다(결과 동일).

## 8. 개인정보 보호

| 대상 | 방법 |
|---|---|
| 주민번호·주소(발급 기록) | **필드 암호화**: AES-256-GCM. 데이터 키는 Windows **DPAPI**(현재 사용자 계정)로 감싸 `%APPDATA%` 에 둔다. DB 파일만 들고 가서는 읽을 수 없다 |
| 목록·검색 | 마스킹 값(`850315-1******`)만. 원문은 증명서를 열 때만 복호화 |
| 강사 원장 | 주민번호·주소를 **두지 않는다**(발급 때마다 입력 — 요구사항 그대로) |
| 작성 중 입력 | 메모리에만. 강사를 바꾸거나 화면을 떠나면 지움 |
| 로그·audit_log | 주민번호·주소 금지. 로거를 넣지 않는 기존 방침 유지 |
| PDF 파일 | 사용자가 고른 곳에 저장. 기본 파일 이름에 주민번호를 넣지 않음(`경력증명서_김으뜸_제2026-152호.pdf`) |
| 외부 전송 | 없음. 업데이트 확인만 GitHub 로(설정에서 끌 수 있게). WebView2 자체의 최초 연결은 앱이 막을 수 없음을 설정 화면에 안내 |
| 보관 기간 | 설정에서 "n년 지난 발급 기록의 주민번호·주소 지우기"(마스킹만 남김) — 선택 기능, D4 |

**DPAPI 의 함정**: 다른 PC 에 백업을 복원하면 데이터 키를 풀 수 없다. 그래서 백업 파일에는 데이터 키를 **백업 비밀번호로 감싼 사본**을 함께 넣는다(Argon2id). 비밀번호를 잊으면 그 백업의 주민번호·주소는 못 읽지만 나머지 자료는 복원된다. → D2 에서 결정.

주민번호 검사: 13자리·생년월일 앞 6자리·7번째 자리(1~4, 외국인 5~8)만 본다. **끝자리 검증 공식은 쓰지 않는다** — 2020년 10월 이후 부여 번호는 공식이 맞지 않는다. 형식이 이상하면 경고만, 발급은 막지 않는다.

## 9. Excel 가져오기

학생명단 앱에서 검증한 **분석(미리보기) → 적용** 두 단계를 그대로 쓴다.

1. 파일 선택(.xlsx/.xlsm, calamine 으로 읽음 — Excel 불필요, **매크로 실행 안 함**)
2. 시트 자동 선택(`강사명단` 우선) · 머리글 줄에서 열 자동 대응(`성명/이름`, `시작날짜/시작일` …), 화면에서 바꿀 수 있음
3. 줄마다 판정:

| 판정 | 예 |
|---|---|
| 정상 | `2022.3.4.` → `2022-03-04` |
| 재직중으로 변환 | 마감날짜가 `현재`·`재직중`·`재직`·빈칸 → `end_date NULL, ACTIVE` (빈칸은 "확인" 표시) |
| 날짜 오류(막음) | `2022.13.4`, 시작 > 종료, 읽을 수 없는 글자 |
| 중복(건너뜀) | 같은 성명 + 프로그램 + 시작일이 이미 DB 에 있음 / 파일 안에서 두 번 |
| 확인 필요 | 같은 사람에 재직중 경력이 여럿 · 기간이 겹침 · 동명이인 의심 |

4. 날짜 형식: `2022.3.4.` · `2022. 3. 4` · `2022-03-04` · `2022/3/4` · Excel 날짜 숫자(셀이 날짜 형식일 때) · `22.3.4`(2000년대로). 형식별 건수를 미리보기에 보여 준다.
5. 강사 짝짓기: 성명으로 기존 강사를 찾는다. **같은 이름이 DB 에 둘 이상이면 자동으로 고르지 않고** 사용자가 고른다.
6. 적용은 한 트랜잭션, 적용 직전 자동 백업, 분석 결과는 Rust 쪽에 들고 있다가 **적용 때 다시 판정**(미리보기와 결과가 어긋나지 않게).
7. `imports` 에 기록, 각 경력에 `import_id` — 잘못 가져왔으면 그 묶음만 찾아 정리할 수 있다.

## 10. 백업·복원

학생명단 앱 방식 그대로:
- 백업은 **SQLite 백업 API**(WAL 이라 파일 복사 금지) → 한 파일로 만들고 → 다시 열어 `integrity_check`·표·버전 확인 → 실패하면 지움.
- 종류: `auto_`(시작 시 하루 1회, 30개 보관) · `manual_` · `before_restore_` · `before_migration_` · `before_import_`.
- 백업 파일에는 §8 의 **비밀번호로 감싼 데이터 키**를 함께 넣는다(수동 백업·다른 PC 이전용).
- 복원: ① 파일 검사(깨짐·다른 앱 파일·**현재보다 높은 스키마 버전** 거절) ② `.restore-pending` 으로 놓고 앱 재시작 ③ 시작 시 지금 자료를 `before_restore_` 로 백업 ④ 교체 ⑤ 마이그레이션 ⑥ 데이터 키 확인(같은 PC면 그대로, 다른 PC면 백업 비밀번호 입력).

## 11. 서버 확장 시 고려사항

| 지금 해 두는 것 | 이유 |
|---|---|
| 모든 표에 `uuid` | 로컬 정수 번호는 서버와 합칠 때 겹친다 |
| `service` 층이 Tauri 를 모름 | 발급 확정·가져오기를 서버 API 로 옮길 때 그대로 |
| 발급 상태를 문자열 상태값으로 | `REQUESTED/APPROVED` 추가만으로 온라인 신청 수용 |
| `created_by = 'local'` | 사용자 계정이 생기면 그 자리에 |
| 양식이 HTML | 서버에서 headless Chromium 으로 같은 결과 |
| 강사 원장에 주민번호 없음 | 온라인 신청에서는 강사가 신청 때 입력 → 지금 흐름과 같음 |

일부러 하지 않는 것: 동기화 로직, 로그인, 권한, REST 계층. 넣으면 지금 버전이 복잡해지기만 한다.

주의할 점: 서버로 가면 **학교 여러 곳**이 한 DB 를 쓸 수 있다. 지금 `school_settings` 가 1행인 것은 서버 전환 때 `schools` 표로 바뀌어야 한다 — 발급 기록은 학교 정보를 복사해 두므로 과거 증명서에는 영향 없다.

## 14. 위험 요소·개선 제안

1. **WebView2 인쇄 API 검증 전** — Phase 5 첫날 스파이크. 대안 경로 확보(§7.5).
2. **DPAPI 는 계정·PC 에 묶임** — PC 교체·Windows 재설치 때 백업 비밀번호 없이는 주민번호를 잃는다. 설정 화면과 첫 실행에 명확히 안내.
3. **동명이인** — Excel 은 이름으로만 묶었으므로 가져오기 때 두 사람이 한 강사로 합쳐져 있을 수 있다. 가져오기 미리보기에서 "같은 이름, 서로 다른 프로그램, 기간 겹침" 을 표시.
4. **종료 처리 누락** — 학년도 말 계약 종료를 잊으면 다음 해 증명서에 `현재` 가 찍힌다. 대시보드 "확인 필요" + (선택) 학년도 말 일괄 종료 기능을 Phase 3 에 포함 제안.
5. **발급일과 경력의 시점 불일치** — 발급일을 과거로 바꿨는데 그 뒤에 시작한 경력을 고르면 모순. 발급일 이후 시작 경력은 경고, 발급일 이전에 끝난 경력만 `~ 종료일` 로 보이는지 등 `domain` 규칙으로 검사.
6. **양식 법적 요건 미확인** — 기존 제목이 '활동 확인서' 인 점, 주민번호 전체 표기가 필요한지(뒷자리 가림 출력 선택지) 교육청 지침 확인을 권함. 출력 시 뒷자리 가림 선택 옵션을 양식 v1 에 넣어 두는 것을 제안.
7. **샘플 파일의 이름 자료** — 가명으로 보이나 확인 전까지 저장소·시험 자료에 넣지 않음. 시험 자료는 새로 만든 가상 자료만.

### 15.1 암호화 키 구조 (D2)

```
데이터 키(DEK, 32바이트 난수) ── 주민번호·주소를 AES-256-GCM 으로 암호화
   │                              (증명서마다 새 nonce, AAD = 증명서 uuid → 다른 행에 옮겨 붙여도 풀리지 않음)
   ├─ DPAPI(현재 Windows 사용자)로 감싼 사본  ─┐
   └─ 복구 비밀번호(Argon2id)로 감싼 사본     ─┴─ 둘 다 DB 의 key_store 표에 저장
```

- 키 사본이 **DB 안에** 있으므로 SQLite 백업 API 로 뜬 자동·수동 백업에도 함께 들어간다.
- **같은 PC 복원**: DPAPI 사본이 풀리므로 비밀번호를 묻지 않는다.
- **다른 PC 복원**: DPAPI 사본이 풀리지 않는다 → 복구 비밀번호를 물어 비밀번호 사본으로 푼다 → 그 PC 의 DPAPI 로 다시 감싸 저장.
- 복구 비밀번호는 설정에서 한 번 정한다(발급 기능을 처음 쓸 때 안내). 정하지 않았으면 백업 화면에 "이 백업은 이 PC 에서만 주민번호·주소를 읽을 수 있습니다" 를 표시한다.
- 비밀번호를 잊어도 **이 PC 에서는** 계속 쓸 수 있고, 설정에서 새 비밀번호로 다시 감쌀 수 있다(DEK 는 그대로라 기존 자료를 다시 암호화할 필요 없음).
- 비밀번호도 DPAPI 도 쓸 수 없으면 주민번호·주소만 읽지 못하고 나머지(성명·경력·발급번호·마스킹 값)는 정상 표시한다.
- 구현 시기: key_store·암호화 = Phase 6, 복구 비밀번호·다른 PC 복원 = Phase 8.

### 15.2 추가 조건 1 — 학년도 말 일괄 종료 (Phase 3)

**자동 종료는 절대 하지 않는다.** 날짜가 지났다는 이유로 상태를 바꾸는 코드는 어디에도 두지 않는다(대시보드는 알리기만 한다).

1. 담당자가 재직중 경력 목록에서 **대상을 직접 체크**(기본 선택 없음)
2. 종료일 지정(공통 1개, 줄마다 바꿀 수 있음), 사유 선택
3. **미리보기**: 줄마다 `2026.03.04 ~ 현재 → 2026.03.04 ~ 2027.02.12`. 시작일보다 이른 종료일 등은 막음 표시
4. [적용] 은 미리보기를 본 뒤에만. 적용 직전 **다시 계산**하고 미리보기 뒤 자료가 바뀌었으면(`state_key` 불일치) 거절
5. 적용 = 한 트랜잭션 + 직전 백업(`before_bulk_end_`) + audit_log 한 줄

### 15.3 추가 조건 2 — 발급일과 경력기간 검사 (Phase 4)

`domain::certificate::check_dates(issued_on, items, today)` 한 곳에서 판정한다. 막지 않고 경고하되, **경고가 있으면 발급 확정 창에서 항목별 확인 체크를 해야 확정 버튼이 켜진다.**

| 코드 | 조건 | 표시 |
|---|---|---|
| `STARTS_AFTER_ISSUE` | 경력 시작일 > 발급일 | **강한 경고.** 해당 줄 빨간 표시 + 미리보기에서도 줄 강조 |
| `ENDS_AFTER_ISSUE` | 종료된 경력의 종료일 > 발급일 | 경고 (발급일 기준으로는 아직 끝나지 않은 경력) |
| `ACTIVE_BUT_PAST_ISSUE` | 재직중 경력인데 발급일이 오늘보다 과거 | 안내 ('현재' 는 발급일 기준 뜻이 됨) |
| `ISSUE_IN_FUTURE` | 발급일 > 오늘 | 경고 |
| `ISSUE_FAR_PAST` | 발급일이 오늘보다 1년 넘게 과거 | 경고 |

### 15.4 추가 조건 3·4 — 발급번호 원칙, Git 안전장치

- 발급번호: D9 그대로. 시험으로 `"  제2026-152호 "` → `"제2026-152호"`, `"2026-152"` → `"2026-152"`(변환 없음)를 고정한다.
- Git 에 들어가면 안 되는 것: DB(`*.db*`), 백업, 로그, PDF, 엑셀 파일(샘플·가져오기 원본), 키·비밀번호 파일, `.env`, 실제 주민번호·주소.
  - `.gitignore` 로 1차 차단
  - `scripts/check-privacy.mjs`: 커밋 대상(스테이지)의 **파일 종류**와 **내용**(주민번호 모양 `YYMMDD-[1-8]NNNNNN`)을 검사. 걸리면 커밋 거절
  - `.githooks/pre-commit` 이 위 검사를 부른다(`npm run hooks:install` = `git config core.hooksPath .githooks`)
  - `npm run check:privacy -- --all` 로 저장소 전체 검사(릴리스 전 필수)
  - 시험에 주민번호 모양 값이 꼭 필요하면 **같은 줄에 `privacy:fake` 표시**가 있어야 통과(가짜임을 사람이 확인했다는 표시)
- 시험 자료는 코드가 만드는 가상 자료만. 샘플 xlsm 은 저장소 밖에 둔다.

### 16.1 기록해 둔 사항

- **esbuild 설치 스크립트 경고** (2026-10-01): `npm install` 때 `esbuild` postinstall 이 allowScripts 에 없다는 경고가 뜬다. 빌드·실행·시험에 문제가 없어 그대로 둔다(사용자 결정). 실제 문제가 생기거나 배포에 영향이 확인되면 대응.
- **임시 아이콘**: `scripts/appicon.png` 로 만든 임시 아이콘을 UI·기능이 어느 정도 완성될 때까지 쓴다(사용자 결정).
- **"설정 완료" 의 뜻**: 증명서에 찍히는 7개 칸이 모두 채워진 상태. 문서 제목·기본 용도는 비울 수 없고, 나머지는 비운 채 저장할 수 있되 대시보드가 빠진 항목을 알린다. 사이드바는 학교명이 있으면 학교명을 보인다.
- **날짜 글자 해석 규칙** (Phase 2, `domain::date::parse_loose`): 점·하이픈·빗금 중 **한 가지** 구분자, 끝 점과 사이 공백 허용, `2022년 3월 4일`, 숫자 8자리, 두 자리 연도는 2000년대. 연도는 1950~2099 밖이면 오타로 거부. 없는 날짜 거부. 구분자를 섞은 값(`2022.3-4`)은 추측하지 않고 거부. `현재`·`재직중`·`재직`·`근무중` 은 날짜가 아니라 재직중 표시(`is_current_word`).
- **경력 수정으로 상태를 되돌릴 수 있다**: 종료 처리(`end`)는 재직중 → 종료 한 방향이고 이미 종료면 `CAREER_ALREADY_ENDED`. 잘못 종료한 것을 되돌리거나 종료일을 고치는 것은 경력 수정(전체 검사를 다시 지남)으로 한다.
- **대시보드 '확인 필요'** (Phase 3): 지금 자료로 객관적으로 가릴 수 있는 것만 — ① 동명이인인데 구분 메모 없음 ② 시작일이 오늘 이후인 재직중 경력 ③ 종료일이 오늘 이후인 경력 ④ 같은 강사의 경력 기간 겹침. 알리기만 하고 고치지 않는다. "기간이 지났는데 재직중" 은 재직중 경력에 예정 종료일이 없어 판단하지 않는다(개선안은 Phase 3 보고).
- **변경 기록(audit_log)**: 강사·경력의 등록·수정·종료·보관·보관 해제, 일괄 종료(건별 + 묶음 1줄). summary 에는 값이 아니라 바뀐 **항목 이름**·건수·종료일·사유만. 바뀐 것이 없는 수정은 기록도 수정 시각도 남기지 않는다. 시험이 이름·메모 값이 새지 않는지 확인.
- **기간 두 쪽 표시**: `domain::date::display_period_parts` 가 (시작, 끝) 을 따로 준다 — 좁은 화면에서 "~" 뒤에서만 줄을 바꾸는 데 쓰고, Phase 5 증명서의 '부터 · 까지' 칸도 이것을 쓴다. `display_period` 도 이 함수를 지난다.
- **발급일 기준 기간** (Phase 4 결정, `domain::certificate::end_on`): 재직중 → `~ 현재` / 종료이고 발급일 ≥ 종료일 → `~ 종료일` / 종료이고 발급일 < 종료일 → `~ 현재` / 시작일 > 발급일 → 증명서에 **넣을 수 없음**(경고가 아니라 선택 불가). 예정 종료일은 보지 않는다. 설계안 §15.3 의 `STARTS_AFTER_ISSUE` 경고는 이 규칙으로 대체됐다.
- **주민번호 입력**: 숫자 13자리만 받고(하이픈·공백 무시) `YYMMDD-NNNNNNN` 으로 맞춘다. 끝자리 검증 공식은 쓰지 않는다. 생년월일이 달력에 없으면 경고만. 오류 문구·`Debug` 에 값이 나오지 않는다.
- **작성 중 값의 자리**: 증명서 작성 화면의 React state 뿐. 내용 확인 요청은 React Query `useMutation` 을 쓰지 않는다(mutation 캐시가 요청 값을 화면을 떠난 뒤에도 들고 있다). `scripts/no-leak.test.mjs` 가 console·브라우저 저장소·Rust print 매크로·증명서 모듈의 log 를 막는다.
- **WebView2 입력 자동완성**: 기본으로 켜져 있어 입력값이 `%LOCALAPPDATA%\<identifier>\EBWebView` 에 남을 수 있다. 앱 시작 시 `SetIsGeneralAutofillEnabled(false)`·`SetIsPasswordAutosaveEnabled(false)` 후 되읽어 확인하고, 설정 → 데이터 관리에 상태를 보인다. 입력 칸에도 `autoComplete="off"`. 실제 앱에서 가상 주민번호·주소를 입력한 뒤 자료·WebView 폴더 463개 파일(UTF-8/16)에 남지 않음을 확인.
- **Phase 5 기술 검증 결과** (WebView2 154, 이 PC): HTML 로딩 ✓ · `PrintToPdfStream` 으로 PDF 를 메모리로 받음 ✓(임시 파일 없음) · A4(209.9×297mm) ✓ · 한글·내장 글꼴 ✓ · 쪽 여백 칸(`@page` margin box)으로 쪽 번호 ✓ · 표 머리글 쪽마다 반복 ✓ · `box-decoration-break: clone` 으로 쪽마다 테두리 닫힘 ✓ · 브라우저 머리글·바닥글 없음 ✓ · `Print`(프린터 지정) 완료 상태(Succeeded) 받음 ✓ · 시스템 인쇄 대화상자(`ShowPrintUI`) 뜸 — 단, 닫힐 때까지 앱이 멈추고 결과를 알 수 없어 정식 출력에는 쓰지 않는다(Phase 6 은 앱의 프린터 고르기 + `Print`).
- **미리보기에 WebView2 내장 PDF 뷰어를 쓰지 않는다**: `HiddenPdfToolbarItems`(저장·인쇄 버튼 숨김)를 설정해도 이 런타임의 PDF 뷰어는 버튼을 그대로 보였다(메인 창·iframe·최상위 문서 모두). 발급 전 문서는 저장·인쇄할 수 없어야 하므로 **pdf.js** 로 PDF 쪽을 그림으로 그린다(같은 PDF 바이트 — 쪽 나뉨이 실제와 같다). 오른쪽 클릭 막음. 브라우저 단축키(Ctrl+P 등)는 메인 창에서 끔.
- **글꼴**: Noto Sans KR 가변 글꼴을 그대로 쓰면 Chromium 이 PDF 에 Type3 로 넣는다 → 굵기 축만 고정한 Regular·Bold 두 파일(글리프 전부 그대로, subset 아님)로 바꿔 TrueType(Type0) 으로 실리게 했다. 라이선스 `licenses/`.
- **출력 모드와 정식 출력 경계**: `render::render(doc, Mode)` — `Mode::Issued(IssuedProof)` 의 증표는 발급 기록에서만 만든다(`IssuedProof::from_issued_record`, Phase 6). `print::output::{issued_pdf, issued_print, save_pdf}` 는 증표를 요구하고 화면에 연결하지 않았다. 사용자에게는 `certificate_preview`(워터마크)만 열려 있다.
- **임시 파일·흔적**: PDF 는 메모리 스트림, 미리보기는 메모리(ArrayBuffer → canvas), 출력 창 DOM 은 작업마다 비움(실측: 끝난 뒤 48바이트 빈 문서). 인쇄 시 스풀 파일은 Windows 스풀러가 관리(인쇄 뒤 지움). 실제 앱에서 가상 주민번호·주소로 미리보기·발급본 PDF·인쇄를 한 뒤 자료·WebView2 폴더 611개 파일과 %TEMP% 를 검사 — 주민번호·주소 없음(IPC 응답은 HTTP 캐시에 남지 않음). 화면 소스의 예시 문구가 개발 서버 캐시에 걸린 것은 예시를 `000000-0******` 로 바꿈.
- **미래 발급일 거부** (Phase 5 결정): `issued_on > 오늘` 은 `CERT_ISSUE_IN_FUTURE` 로 증명서를 만들지 않는다(§15.3 의 `ISSUE_IN_FUTURE` 경고를 대체). 1년 넘은 과거는 경고.
- **doc_hash 는 HMAC-SHA256** (Phase 6 결정): 정본 글(`CERTDOC/1`, 고정 순서 `키=값` 줄, 개인정보 포함)을 그대로 SHA-256 하면 주민번호 공간이 작아(생년월일 + 7자리) DB 만 가진 사람이 해시를 대조해 주민번호를 되찾을 수 있다. 그래서 데이터 키에서 뽑은 해시 전용 키(`HMAC(DEK, "careercert/doc-hash/v1")`)로 HMAC 한다. 정본 글·해시 입력은 로그·오류에 내지 않는다(`Zeroizing`).
- **review_token**: 개인정보를 뺀 정본 글의 SHA-256. 내용 확인 때 화면에 주고, 발급 확정 때 서버가 다시 만든 값과 비교 — 강사·경력·설정이 그 사이 바뀌면 거절. 주민번호·주소 칸은 화면이 그대로 보내므로 비교 대상이 아니다.
- **발급번호 키**: `issue_no` 는 앞뒤 공백만 정리한 원문을 그대로 찍고, 중복 검사는 모든 공백을 뺀 `issue_no_key` 로도 한다(`2026-가- 0001` 과 `2026-가-0001` 은 같은 번호). 둘 다 UNIQUE, 취소된 발급도 포함.
- **암호화 구조**: 데이터 키(32바이트, 무작위) 하나를 DPAPI(CurrentUser + 앱 entropy)로 감싸 key_store 에 둔다. 발급마다 무작위 12바이트 nonce, AAD `careercert/certificate/v1|{uuid}|{key_id}`(다른 발급 행으로 암호문을 옮기면 풀리지 않음). 다른 Windows 사용자·PC 로 DB 만 옮기면 풀 수 없다 — `recovery_blob` 칸은 Phase 8(백업·복원)에서 채운다.
- **발급 증표 봉인**: `IssuedProof` 는 `service::issuance` 안에서만 만든다(생성자 비공개). 정식 출력 함수(`print::output::issued_*`)는 증표를 요구하므로 작성 중 문서로 정식 출력하는 길이 없다. `dev_print_spike` 는 미리보기 모드만, release 에서는 거절. `npm run check:print` 도 미리보기 모드로 쪽 수만 잰다.
- **출력 이력**: PDF 저장은 사용자가 [취소]하면 아무것도 남기지 않고, 저장 실패는 FAILED. 인쇄는 WebView2 `Print` 가 `Succeeded` 일 때만 SUCCESS. 파일 경로·주민번호·주소는 남기지 않는다(파일 이름도 남기지 않음). 저장한 PDF 는 앱이 지우지 않는다.
- **Phase 6 실측** (sandbox 앱): 발급(경고 0개 → 체크 칸 없음 / 경고 3개 → 3개 다 체크해야 버튼 켜짐), 공백만 다른 발급번호 거절, 내용 확인 뒤 설정을 바꾸면 `CERT_CHANGED`, Microsoft Print to PDF 인쇄 성공·이력, PDF 저장 성공·이력, 재직중 경력을 종료한 뒤 다시 저장한 발급본도 '현재'·옛 담당자 그대로, 취소 후 인쇄·PDF·재취소 거절. 자료 폴더(DB·WAL·백업)·WebView2 폴더 622개 파일 바이트 검사 — 가상 주민번호·주소 0건(가린 주민번호·발급번호는 보임 — 검사 자체 확인).
- **발급이력 정렬** (Phase 7): 최근 발급순 = 발급일 내림차순, 같은 날은 나중에 확정한 것 먼저. 발급일을 과거로 잡은 건은 확정 시각이 최근이어도 그 날짜 자리에 놓인다(목록에 보이는 날짜와 차례가 맞도록). 대시보드 "최근 발급"만 확정 차례.
- **복호화하지 않는 길** (Phase 7): `service::history`·`commands::history` 는 `Meta`(암호문·key_id·doc_hash 칸 없음)·경력 사본·출력 이력만 읽는다. 시험이 암호문과 key_store 를 일부러 망가뜨린 뒤에도 목록·상세·새 초안·대시보드·복구 상태가 그대로 되는지 확인하고, `scripts/no-leak.test.mjs` 가 이 모듈에서 복호화 함수 이름과 암호문 칸 이름을 막는다. 상세의 주민번호는 `masked_rrn` 뿐, 주소는 보이지 않는다.
- **새 증명서 작성의 경력 연결** (Phase 7): 원래 사본의 `source_career_id` 로 지금 원장의 경력을 찾는다. 보관되었거나 오늘 발급일로 넣을 수 없으면 "연결하지 못함" 으로 세어 알린다(조용히 빼지 않음). 원래 없던 경력은 선택하지 않고 건수를 알린다. 원래 강사가 보관·삭제되었으면 강사를 잇지 않고 다시 고르게 한다 — 이때 처음 고른 강사에는 가져온 용도·표시 방식·원본 연결을 남기고, 그 뒤 다른 강사로 바꾸면 원본 연결도 끊는다.
- **복구 상태 구조** (Phase 7): `service::history::recovery` 가 key_store 의 `recovery_blob` 유무만 센다 — 키 없음 NO_DATA, 사본 없는 키가 있으면 NOT_SET, 모두 있으면 READY. Phase 8 이 복구 사본을 채우면 화면 안내가 저절로 "준비됨" 으로 바뀐다.
- **인쇄 매수**: `service::issuance::MAX_COPIES = 5` (`check_copies`, 출력 기록도 검사). DB CHECK 는 Phase 6 의 1~20 을 그대로 둔다(SQLite 는 CHECK 를 바꾸려면 표를 다시 만들어야 해서 — 서버 검사가 먼저 막는다).
- **작성 화면 경력 목록 캐시 버그 수정** (Phase 7 실측 중 발견): 다른 화면에서 경력을 보관·종료해도 작성 화면 경력 선택(`cert-choices`)이 최대 30초 옛 목록을 보였다. 경력 변경 시 `cert-choices` 도 새로 읽고, 작성 화면에 들어올 때마다 새로 읽게 했다(내용 확인은 원래 서버가 지금 원장으로 다시 만들어 잘못 발급되지는 않았다).
- **Phase 7 실측** (sandbox 앱): 찾기(발급번호 일부·성명·취소 필터·시작일만·잘못된 기간 안내·조건 지우기), 상세(원장 종료 뒤에도 "현재"·옛 담당자), 재출력 인쇄(Microsoft Print to PDF, 원본과 같은 1쪽) 직후 이력 갱신, 서버 6부 거절, 새 증명서 작성(빈 주민번호·주소·발급번호, 오늘, 지금 원장 기준 기간, 확정 창 "참고한 발급", 새 기록에 원본 연결), 취소된 건에서 시작(안내 + 경력 4건 중 3건 연결·1건 보관 안내·원래 없던 1건 미선택), 상세에서 취소 직후 버튼 사라짐·목록 갱신, 대시보드 발급 현황, 설정 복구 미설정 안내. 자료·WebView2 폴더 645개 파일 바이트 검사 — 가상 주민번호·주소 0건.
